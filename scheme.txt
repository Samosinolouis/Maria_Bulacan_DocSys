SECTION 4: CARDINALITY MATRIX & INTEGRITY RELATIONSHIPS
================================================================================

1. users -> documents (created_by_user_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Mandatory FK. A document must have an authoring clerk.
   - Deletion: RESTRICT. A user who logged active documents cannot be hard-deleted.

2. users -> documents (assigned_to_user_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Optional FK. Document can be assigned to a specific officer for drafting/review.
   - Deletion: SET NULL.

3. documents -> attachments (document_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Mandatory FK. Every attachment belongs to exactly one docket.
   - Deletion: CASCADE. Archiving/deleting document purges attachment metadata.

4. documents -> transmissions (document_id)
   - Cardinality: One to One (1:1)
   - Enforcement: UNIQUE FK. A document possesses at most one active outward transmittal record.
   - Deletion: CASCADE.

5. venues -> event_bookings (venue_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Mandatory FK.
   - Deletion: RESTRICT. Active municipal venues cannot be deleted while reservations exist.

6. event_bookings -> event_attendees (event_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Mandatory FK.
   - Deletion: CASCADE. Deleting an event deletes attendee entries.

7. documents -> audit_logs (document_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Optional FK. Audit log persists even if document record is archived.
   - Deletion: SET NULL. Preserves immutable history.

8. users -> audit_logs (user_id)
   - Cardinality: One to Many (1:N)
   - Enforcement: Mandatory FK.
   - Deletion: RESTRICT. Preserves statutory chain of custody.

SECTION 5: ARTA RA 11032 STATUTORY RULES & CONSTRAINTS
================================================================================

1. 72-Hour Turnaround Rule (Section 21, RA 11032):
   - Simple transactions must be completed within 3 working days (72 hours).
   - Complex transactions: up to 7 working days.
   - Highly technical transactions: up to 20 working days.
   - sla_deadline = date_received + INTERVAL '72 hours'
   - If (CURRENT_TIMESTAMP > sla_deadline AND status NOT IN ('APPROVED', 'ENDORSED', 'DENIED', 'CLOSED')):
       is_overdue = TRUE
       Escalation notification dispatched to Municipal Administrator dashboard.

2. Double-Booking Prevention Rule (Venues):
   - A new booking with status 'CONFIRMED' cannot overlap with an existing 'CONFIRMED'
     booking for the same venue_id on the same booking_date:
     NOT EXISTS (
       SELECT 1 FROM event_bookings e
       WHERE e.venue_id = NEW.venue_id
         AND e.booking_date = NEW.booking_date
         AND e.status = 'CONFIRMED'
         AND e.id != NEW.id
         AND (NEW.start_time < e.end_time AND NEW.end_time > e.start_time)
     )

3. Finite State Lifecycle Transitions:
   RECEIVED -> SCREENING -> PREPARATION -> REVIEW -> APPROVED / ENDORSED / DENIED -> TRANSMITTED -> CLOSED
   - Any status change triggers an automatic, unalterable insertion into audit_logs.
